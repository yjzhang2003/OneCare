# OneCare 品牌与题目转向设计

## 状态

用户于 2026-07-17 确认先做展示层转向，并要求直接实施。系统架构、真实 AI、IoT、客服、工单、配件与回访系统集成留待后续讨论。

## 目标

在不改变 Next.js 技术栈、应用脚手架和现有飞书 OAuth 登录行为的前提下，把当前汽车用户洞察展示站转向为“AI 驱动的海信用户服务全链路闭环引擎”方案展示。

产品、仓库与网页品牌统一使用 `OneCare`，仓库名和网页标题不得出现 `Hisense`；网站正文可以明确说明方案服务于海信集团。

## 范围

本次包含：

- 首页品牌、价值主张、挑战、能力与目标指标文案转向；
- 登录后工作台改为静态的服务闭环指挥台预览；
- 页面标题、描述、包名与无障碍品牌标签更新为 OneCare；
- README、AGENTS 项目基线与 TECH_STACK 当前产品名称和边界更新；
- GitHub 仓库名称改为 `OneCare`；
- 在不破坏现有生产 OAuth 回调的前提下，将 Vercel 项目改为不含 Hisense 的 OneCare 名称，并记录实际生产地址。

本次不包含：

- 系统架构设计或架构决策；
- 真实 AI 推理、IoT 数据、VOC 数据或业务系统接入；
- 新增数据库、API、队列、智能体或后台任务；
- 改动飞书 OAuth 协议、Cookie、会话或认证路由行为；
- 把静态演示数据描述为真实在线数据。

## 展示设计

### 首页

保留现有编辑式工业视觉骨架与登录入口，品牌改为 OneCare。首页讲述海信从设备制造向智能生活服务伙伴转型的命题，并以四项静态能力卡表达：

1. VOC 智能分析；
2. 智能预诊；
3. 协同调度；
4. 闭环追踪。

核心目标用“服务周期缩短、重复上门降低、满意度提升”表达。页面必须保留“方案原型、未接入真实业务数据或 AI 服务”的边界说明。

### 工作台

保留受保护页面、飞书身份展示与退出行为。静态工作台改为服务闭环指挥台，展示设备风险信号、待协同服务队列与四个闭环模块。所有状态和指标均标记为静态预览或方案演示。

### 视觉

沿用现有排版、色板、响应式断点与动画，避免为本次题目转向引入新依赖或大规模样式重构。品牌标记从 `AI` 改为 `1C`，英文操作标签转向 `LISTEN / PREDICT / DISPATCH / CLOSE`。

## 平台命名与生产边界

- GitHub 仓库目标名称：`OneCare`。
- npm 包名：`onecare`。
- Vercel 项目优先使用 `onecare`；若平台名称冲突，则使用不含 Hisense 的最短 OneCare 变体，并在 README 记录实际地址。
- 修改 Vercel 项目名称或域名后，必须检查稳定生产别名和 `FEISHU_REDIRECT_URI`。如果新默认域名未在飞书后台登记，不得删除或失效现有 `auto-insight-omega.vercel.app` 回调别名；需要飞书后台变更时应明确报告而不是声称登录已迁移。
