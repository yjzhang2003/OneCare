# OneCare 固定 Top Bar 与 Hero 精简设计

## 状态与优先级

本规格记录 2026-07-18 对 OneCare 首页 Top Bar 和 Hero 的增量修改。它继承海信品牌展厅与文字按钮交互规格，并覆盖其中 Top Bar 使用 `sticky`、窄屏隐藏“首页”以及 Hero 保留原型状态文案和故障浮卡的实现。

## 目标

让 Top Bar 在整个页面滚动过程中始终可见，把“首页、四个视角、五层引擎、团队”整体靠右排列，并删除 Hero 中干扰主叙事的“方案原型，未接入真实数据”文案和“冰箱温控异常”白色卡片。

## Top Bar 规则

- Top Bar 使用 `position: fixed`，固定于视口顶部，左右贴边，滚动时不得离开视口。
- 桌面高度保持 `64px`；`640px` 以下移动端保持两行布局和 `118px` 高度。
- 页面根容器分别使用 `64px` 和 `118px` 的顶部内边距补偿固定栏，不允许 Header 覆盖 Hero 或认证提示。
- 桌面网格使用 `auto minmax(0, 1fr) auto`：品牌在左，章节导航占中间弹性列并靠右，登录按钮在最右。
- 章节导航始终包含“首页、四个视角、五层引擎、团队”，不得在 `1100px` 以下隐藏“首页”。
- 桌面和移动端章节导航均使用 `justify-content: flex-end`；移动端允许横向滚动作为极窄屏兜底。
- Top Bar 的 `z-index` 必须高于 Hero、Tab、卡片和页面动效。
- `#perspectives`、`#architecture`、`#team` 的滚动定位必须为固定栏预留空间，点击导航后标题不得被遮挡。

## Hero 精简规则

- 删除 Hero 中未登录状态的“方案原型 · 未接入真实业务数据”。
- 同时删除已登录状态原先复用该位置的“用户名，欢迎回来”，不保留空占位。
- 删除“服务信号 001 / 冰箱温控异常 / 已识别 · 待预诊”白色浮卡及其全部响应式样式。
- 保留主标题、介绍、两个 CTA、场景大图和右上角温度信号动效。
- 页尾继续保留原型边界说明，避免把方案能力描述为生产能力。

## 组件范围

- `app/landing-content.tsx`：删除 `session-copy` 和 `showroom-hero__case`。
- `app/landing-content.test.tsx`：锁定删除内容和章节导航完整性。
- `app/globals.css`：实现固定栏、右对齐、顶部补偿和锚点补偿；移除废弃 Hero 样式。

不修改飞书认证 URL、按钮动效、四视角交互、五层引擎、团队卡片、页尾原型说明或 Production 配置。

## 验收标准

1. 页面中不存在 `.session-copy`、`.showroom-hero__case`、“方案原型 · 未接入真实业务数据”或“冰箱温控异常”浮卡文本。
2. 未登录和已登录状态均保留正确登录/工作台链接，但不显示欢迎行。
3. 1440px 与 390px 浏览器中 Top Bar 的计算样式为 `position: fixed`、`top: 0px`，滚动到页尾后边界框仍位于视口顶部。
4. 四个章节导航在桌面和移动端都存在，计算样式为右对齐，无横向页面溢出。
5. 点击三个章节锚点后，目标标题位于固定栏下方。
6. 单元测试、Lint、类型检查、生产构建、浏览器验收通过后，只更新非生产 Vercel Preview。

## 原型边界

Hero 的原型提示被删除不代表系统已接入真实数据。页尾原型声明继续作为全页统一边界说明。

## 中文命名补充

- 面向辅助技术的品牌标签使用“万护 OneCare”；
- README 与当前技术说明首次提及产品时使用“万护 OneCare”；
- `onecare` npm 包名、代码命名、CSS 变量、GitHub 仓库名、Vercel 项目名、域名和 OAuth 回调地址保持不变；
- 历史规格和实施计划保留当时的 `OneCare` 表述，不做无意义的批量改写。

验收时必须确认首页和工作台均出现“万护”，页面元数据包含“万护 OneCare”，且现有 URL、认证路径、布局和交互不受影响。
