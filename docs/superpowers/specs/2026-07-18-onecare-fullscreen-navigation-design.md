# 万护 OneCare 整屏章节导航与标题统一设计

## 状态与优先级

本规格记录 2026-07-18 对万护 OneCare 展示站一级信息架构、页面切换和章节标题的增量调整。它继承现有海信品牌展厅视觉、固定黑色 Top Bar、MiSans 字体、药丸按钮、圆角白卡和飞书登录规则，但覆盖原先由锚点驱动的单页纵向长滚动结构。

如果本规格与下列既有规则冲突，以本规格为准：

- Top Bar 的“首页 / 四个视角 / 五层引擎 / 团队”不再滚动到同一条长页面中的锚点，而是切换四个独立整屏章节；
- 一级章节不再混用“中文编号”“英文 eyebrow”和“英文斜线标签”；
- “方案目标”不再作为与四个一级入口并列的独立章节，而是归入“五层引擎”页面；
- 页尾不再跟在所有章节之后统一出现，而是位于“团队”页面的内容末尾。

## 目标

把当前从上到下连续堆叠的首页重构为四个风格一致、边界清楚的整屏章节，让评审点击 Top Bar 后感受到整个视口横向切换，而不是页面向下跳到另一个锚点。

本批次同时统一一级页面的标题结构与语言，但暂不统一四视角面板、五层蓝图、团队卡片等页面内部正文的全部字阶。

## 采用方案

采用“单 URL、四个整屏章节、每页独立纵向滚动”的客户端页面切换器。

选择该方案的原因：

- 相比横向 `scroll-snap`，它不会让五层引擎等长内容与视口高度相互干扰；
- 相比拆成四条 Next.js 路由，它可以保持连续的横向过场、固定 Top Bar 和现有服务端内容组合方式；
- 四个章节继续复用现有组件与数据，不复制页面骨架；
- URL Hash 可以保留深链、刷新恢复和浏览器前进后退，而不引入路由目录重构。

本批次不实现触控拖拽、无限循环、自动播放、分页圆点或真实多路由页面。

## 一级页面模型

一级页面固定为四个，顺序与 Top Bar 完全一致：

| 索引 | Hash | 导航文字 | 统一小标题 | 内容范围 |
| --- | --- | --- | --- | --- |
| `0` | `#home` | 首页 | `00 · 首页` | Hero、产品主张、飞书登录入口 |
| `1` | `#perspectives` | 四个视角 | `01 · 四个视角` | 用户、客服、工程师、后台 Tab 演示 |
| `2` | `#architecture` | 五层引擎 | `02 · 五层引擎` | 感知—诊断—编排—服务—学习与方案目标 |
| `3` | `#team` | 团队 | `03 · 团队` | 三位成员能力占位、原型边界与页尾 |

“方案目标”保留“更短服务周期 / 更低重复上门 / 更高用户满意”的内容，但降为“五层引擎”页内部的二级内容，不出现在 Top Bar，也不使用新的一级编号。

## 标题与语言规范

### 一级小标题

四个一级页面只能使用“二位数字 + 中文名称”的格式：

```text
00 · 首页
01 · 四个视角
02 · 五层引擎
03 · 团队
```

统一样式：

- MiSans；
- 桌面端 `15px`，移动端 `14px`；
- 字重 `600`；
- 青绿色 `#007D79`，深色图片上使用浅青色 `#8FE8E3`；
- 字距 `0.02em`；
- 与主标题间距 `18px`；
- 不使用全大写英文、斜线、英文 eyebrow 或额外胶囊标签。

首页原有“万护 ONECARE · AI 用户服务闭环引擎”不再占用一级小标题位置。品牌信息继续由固定字标、页面标题和正文表达。

### 一级主标题与导语

四页共用同一个标题组件和字阶令牌：

- 主标题：桌面端 `clamp(36px, 4vw, 48px)`，移动端 `clamp(30px, 8.8vw, 36px)`，字重 `600`，行高 `1.15`；
- 导语：桌面端 `18px`，移动端 `17px`，行高 `1.7`；
- 最大文字宽度、上下间距和对齐规则由共享组件控制；
- 首页可以在同一字阶令牌基础上保留两行 Hero 标题和图片叠字布局，不回到超大标题；
- 页面内部的角色标题、蓝图层名、输入输出字段、团队能力文字暂不纳入本批次统一范围。

所有一级小标题均使用中文。英文只允许出现在页面内部确有语义的内容中，例如五层能力的英文辅助名；不得再用英文替代一级章节名称。

## 整屏布局

### 固定外壳

- Top Bar 保持 `position: fixed`，桌面端 `64px`、移动端 `118px`；
- Top Bar 下方建立一个高度为剩余可视区域的页面视口；
- 桌面端视口高度为 `calc(100dvh - 64px)`，移动端为 `calc(100dvh - 118px)`；
- 浏览器不再负责四个一级页面之间的纵向滚动；页面切换器裁切横向溢出；
- 每个一级页面拥有自己的纵向滚动容器，长内容只在当前页面内部滚动。

### 页面内容

- 首页 Hero 至少填满首页可视区域，不显示其他章节的内容边缘；
- 四视角页进入后从统一标题开始，随后显示角色 Tab 和大型角色面板；
- 五层引擎页依次显示统一标题、五层蓝图和方案目标；
- 团队页依次显示统一标题、团队卡片和黑色页尾；
- 非当前页面必须从可访问性树和键盘导航顺序中移除，不能让用户 Tab 到屏幕外的控件；
- 切换到目标页面时，其独立滚动位置重置到顶部；重复点击当前页面不重置滚动位置，也不重复播放过场。

## 导航与 URL

- Top Bar 四个入口继续使用真实 `href`：`#home`、`#perspectives`、`#architecture`、`#team`，为浏览器历史和复制链接保留明确地址；
- JavaScript 可用时，点击由页面切换器接管并执行横向过场；
- 当前入口使用 `aria-current="page"`，并沿用青绿色活动短线；
- 首次加载没有 Hash、Hash 为空或 Hash 不受支持时默认显示首页；
- 首次加载合法 Hash 时直接显示对应页面，不先播放从首页穿越多页的动画；
- 页面切换后使用 History API 写入 Hash；
- 浏览器后退、前进和直接修改 Hash 都必须同步当前页面；
- 页面切换不得重新请求服务端数据，不得改变飞书登录和工作台链接。

## 横向过场

- 从低索引进入高索引：当前页向左退出，目标页从右侧进入；
- 从高索引进入低索引：当前页向右退出，目标页从左侧进入；
- 页面之间按目标索引直接切换，不逐页播放经过的中间章节；
- 动画时长为 `520–620ms`，使用平滑但克制的缓动；
- 过场只改变 `transform` 和必要的轻微透明度，不能造成布局重排；
- Top Bar、认证提示和当前页内部的 Tab 状态不参与整屏平移；
- `prefers-reduced-motion: reduce` 下取消位移动画并立即显示目标页；
- 动画过程中禁止重复触发导致页面堆叠，但最终必须以最后一次明确导航为准。

## 组件边界

### `ShowcaseNavigator`

新增一个聚焦的 Client Component，职责仅包括：

- 保存当前一级页面索引；
- 解析和同步 Hash；
- 计算切换方向；
- 为 Top Bar 提供当前页和导航方法；
- 为四个页面设置活动、离场、入场和隐藏状态；
- 保存每页纵向容器引用并在目标切换时重置滚动。

它不负责四视角 Tab、认证、业务数据或页面文案。

### `ShowcasePageHeading`

新增共享的服务端友好标题组件，接受 `index`、`label`、`title`、`intro` 和深浅色调。四个一级页面都通过它或其 Hero 变体使用同一套小标题与主标题令牌。

### 现有组件复用

- `PerspectiveTabs` 继续只管理四个角色的二级 Tab；
- `ServiceBlueprint` 继续展示五层路径；
- `OutcomeStatement` 移入五层引擎页内部；
- `SiteFooter` 移入团队页末尾；
- `SiteHeader` 继续负责品牌、四个入口和飞书登录，但从页面切换器读取活动页面；
- 不复制 `PerspectiveTabs`、`ServiceBlueprint`、团队卡片或飞书认证代码。

## 响应式行为

### 桌面与平板

- 页面只在水平方向切换；
- 每个页面内部保持当前响应式栅格；
- Top Bar 四个入口保持右对齐和一致字号。

### 手机

- 继续使用两行固定 Top Bar；
- 一级入口在 Top Bar 内允许横向滚动，但字号不得缩小；
- 整屏页面仍通过点击入口切换，不增加依赖手势的唯一操作方式；
- 页面内部继续单列布局并独立纵向滚动；
- 不允许页面级横向溢出或浏览器横向滚动条。

## 可访问性与降级

- Top Bar 使用 `nav`，当前页入口包含 `aria-current="page"`；
- 非活动页面设置 `aria-hidden="true"` 并使用 `inert` 或等价机制移出焦点顺序；
- 页面切换完成后，将焦点移动到目标页的一级标题，但鼠标点击时不制造持续可见的焦点框；
- 键盘用户可以通过 Top Bar 链接完成全部页面切换；
- 二级四视角 Tab 继续支持左右方向键、`Home` 和 `End`；
- 无动画偏好下保留横向过场，减少动效偏好下立即切换；
- JavaScript 失效时保留服务端渲染的首页和飞书登录入口；四个整屏章节切换属于增强交互，需要 JavaScript 才能运行。

## 测试策略

先按 RED → GREEN 锁定行为：

1. 首页只显示一个活动一级页面，四个页面名称和 Hash 顺序固定；
2. 点击“四个视角”后更新活动页面、`aria-current` 和 URL Hash；
3. 从团队返回首页时使用反向状态；
4. 浏览器 Hash 变化能够恢复对应页面；
5. 非活动页面不可聚焦；
6. 重复点击当前入口不重置当前页滚动；
7. 一级小标题只出现四个规定的中文格式，不再出现 `FIVE-LAYER ENGINE`、`TEAM CREDITS` 或 `03 / OUTCOME`；
8. 四视角内部 Tab 键盘行为、飞书登录链接、工作台链接和现有认证测试保持通过。

CSS 位移方向、固定栏高度、独立纵向滚动、移动端溢出、减少动效和焦点行为通过真实浏览器在 `1440 × 900` 与 `390 × 844` 下验证。

## 非目标

本批次不包含：

- 四个角色的真实独立业务页面或 AI 聊天智能体；
- 真实 IoT、VOC、客服、工单、配件、回访或 AI 数据接入；
- 五层系统架构细化；
- 团队真实姓名、照片和履历填充；
- Dashboard 视觉重构；
- Production 部署、Vercel 环境变量或飞书配置修改；
- 仓库推送、Pull Request 或合并。

## 验收标准

1. Top Bar 固定显示“首页 / 四个视角 / 五层引擎 / 团队”，并准确标记当前页。
2. 点击任一入口后，整个内容视口按索引方向横向切换，Top Bar 不移动。
3. 四个一级页面各自独立纵向滚动，切换时不露出相邻页面。
4. 一级小标题严格统一为四个中文格式，一级主标题和导语使用共享字阶。
5. “方案目标”位于五层引擎页内部，团队页末尾包含黑色页尾。
6. URL Hash、刷新、浏览器前进后退和非法 Hash 回退行为正确。
7. 非活动页面不进入键盘焦点顺序，减少动效偏好下无横向位移动画。
8. 现有四视角 Tab、飞书登录、工作台和认证行为不回归。
9. 单元测试、运行时测试、Lint、类型检查、生产构建、`git diff --check` 和桌面/手机浏览器验收通过。
10. 只发布非 Production Preview 供用户确认，不改变 Production。

## 实施验证记录

2026-07-18 的实现采用四个绝对定位页面和 `before / active / after` 三种状态。非活动页位于视口左右两侧、设置 `inert` 与 `aria-hidden`，活动页拥有独立纵向滚动。

真实浏览器在 `1440 × 900` 与 `390 × 844` 下确认：

- Top Bar 分别为 `64px` 与 `118px`，页面视口准确填满剩余高度；
- 页面正向和反向切换均具有正确方向，跳页时不显示中间页面；
- 目标页切换时滚动归零，重复选择当前页保留滚动位置；
- URL Hash、History 后退、活动导航与活动页面保持一致；
- 页面宽度无横向溢出；
- 鼠标切换不产生常驻标题焦点框，键盘激活会在过场后聚焦目标标题；
- `prefers-reduced-motion: reduce` 下页面 transition 为 `none`；
- 浏览器控制台无错误或 hydration 警告。Next Image 的 Hero `priority` 资源在自动化反复改动视口时出现一次 preload 未及时使用的性能提示，不影响页面功能，也未通过删除 LCP 图片预加载来掩盖提示。
