# OneCare 首页“服务信号纪录片”视觉重构设计

## 状态

用户于 2026-07-17 确认当前首页的卡片、小标签与小字号过多，整体接近常见 AI/SaaS 模板，并同意把首页改为“一条服务信号贯穿的滚动叙事”。

本规格是对 `2026-07-17-onecare-homepage-design.md` 的视觉与编排升级。原规格中的产品内容、路由边界、认证行为、静态数据边界和 Preview 交付要求继续有效；与本规格冲突的卡片式布局要求，以本规格为准。

## 目标

让比赛评审像观看一段连续的服务纪录片一样理解 OneCare：一个冰箱温控异常信号如何被发现、诊断、编排、执行并沉淀为下一次改善。

首页需要实现以下变化：

1. 从“多个等权模块”转为“一条有起因、转折和结果的连续叙事”；
2. 从“小卡片解释功能”转为“大场景表现角色与系统关系”；
3. 从“标签标注技术感”转为“线路、信号、尺度和运动表达技术感”；
4. 保留海信参考青绿、黑、白的品牌方向，但让青绿只承担信号和关键状态；
5. 保留 OneCare 现有内容、飞书登录和多页面规划，不提前实现角色页面或真实 AI 能力。

## 受众与观看方式

第一受众仍是比赛评审和方案决策者。桌面端是主要展示环境，页面也必须在手机上完整可读。

推荐观看路径：

1. 首屏看到核心主张与正在出现的异常信号；
2. 随滚动进入“冰箱温控异常”案例；
3. 同一条信号依次经过用户、客服、工程师和后台四个视角；
4. 视角交接自然显露“感知—诊断—编排—服务—学习”五层系统；
5. 最后看到问题解决、知识回流和团队署名。

页面即使没有滚动动画，也必须按同一顺序呈现完整内容。

## 视觉概念

### 核心隐喻：一条有温度的服务信号

一条青绿色信号线贯穿首页。它不是纯装饰，而是叙事主角：

- 在首屏表现为设备温度异常的微弱脉冲；
- 在用户场景中成为一条主动提醒；
- 在客服场景中成为被理解和补全的服务上下文；
- 在工程师场景中成为诊断与配件路线；
- 在后台场景中成为 VOC 与服务质量的回流；
- 在五层架构中闭合为持续学习的循环。

每个场景使用同一套线路语言，避免为每个章节创造互不相关的插画或卡片。

### 视觉气质

整体采用“克制的编辑式工业纪录片”：

- 中文标题使用中等尺度，与正文、线路和场景共同形成层次，不用夸张字号制造冲击；
- 使用适度非对称分栏、纵向章节编号和均衡留白，保持方案信息密度；
- 系统结构通过直线、折线、节点、温度刻度和状态变化表达；
- 青绿是唯一高强度强调色，黑白承担主要画面；
- 保留宋体标题与工业窄体标记的组合，但英文微型标签只用于必要的导航和状态；
- 不使用紫色渐变、玻璃拟态、发光悬浮卡、通用机器人图标或粒子宇宙背景。

互联网参考只用于提取原则，不复制品牌资产或具体页面：

- Pentagram Coqual 的编辑式报头与大色块层级；
- Nothing 的透明工程结构与“展示内部机制”原则；
- Polestar 的科学产品主义、克制色彩和精确标记；
- scrollytelling 的章节推进方式；
- IBM 技术图表中直接标注、减少冗余和用线型表达关系的原则。

## 页面编排

### 1. 页头

继续复用 `SiteHeader` 的品牌、锚点和登录入口。视觉上降低页头高度和边框存在感，使它像纪录片目录而非应用工具栏。

导航文字调整为叙事章节语义：

- 服务旅程：`#journey`；
- 五层引擎：`#architecture`；
- 团队：`#team`。

不增加移动菜单状态。移动端仍允许横向滚动导航。

### 2. 首屏：异常发生之前

首屏保留“让每一次服务，都比问题更早一步”，但从左右两栏的营销 Hero 改为更连贯的叙事起点：

- 标题保持两行以内的中等尺度，不跨栏、不越界，不挤压场景信息；
- 冰箱温度刻度和微弱波形作为首个业务线索；
- OneCare 圆形信号核心缩小为路径起点，不再与标题争夺视觉中心；
- 产品介绍使用可舒适阅读的导语字号，不使用多个小状态标签；
- 飞书登录/工作台入口继续存在；
- 原型说明移到首屏底部的单行注记。

首屏不添加真实设备图片或外部素材依赖，以 CSS 线条、排版和已有数据完成视觉。

### 3. 服务旅程：四个视角接力

移除当前四列 `role-grid` 和四张等尺寸 `RoleCard`。四个角色改为连续的四个场景，每个场景至少占据桌面端约 `75vh`：

1. 用户：以“冰箱好像不太冷了”作为场景对白，信号从设备主动提醒进入对话；
2. 客服：同一问题被压缩为结构化上下文，突出“一次理解，不再重复描述”；
3. 工程师：诊断、建议配件和上门路径沿信号线展开，突出“一次带对”；
4. 后台：本次处理进入 VOC 聚类与质量回流，突出“一次解决，持续学习”。

每个场景只显示一个主标题、一句角色价值和最多三条关键证据。原有能力词保留在内容数据中，但不渲染为胶囊标签；它们改为沿线路排列的直接文本或清晰动作词。

四个场景使用交替的黑底、纸白和浅青区块形成章节节奏。不得把它们重新包装成带圆角和阴影的卡片。

### 4. 五层引擎：一张服务蓝图

移除当前五列 `SignalFlow` 卡片。五层架构改为一张连续蓝图：

- 桌面端以一条横向折线路径串联五个清晰层名，层名不压过输入、动作和输出；
- 输入、动作、输出直接标注在路径附近，不再放进三个独立小框；
- 当前案例的关键事件作为青绿节点叠加在对应层；
- “学习”节点通过回路线重新连接“感知”，明确闭环；
- 章节允许横向视觉，但页面本身保持纵向滚动，不引入水平滚动交互。

移动端将蓝图转换为单列纵向路线。层级顺序、输入、动作和输出保持完整，闭环通过末端回指文案表达，不绘制容易遮挡内容的复杂回线。

### 5. 结果段：一次就好

当前独立的冰箱方案路径不再重复五个步骤，而是在四视角和五层架构之后形成结果段：

- 章节标题“一次就好”；
- 三个目标“更短服务周期 / 更低重复上门 / 更高用户满意”以同一行或连续三段的重点文字呈现；
- 明确这些是方案目标，不使用伪造数字；
- 一条回流信号把结果连接到“下一次更早发现”。

### 6. 团队：杂志署名页

移除三张成员卡。团队区域改为杂志署名式三栏：

- 三个清晰但克制的序号 `01 / 02 / 03`；
- 角色方向作为主要标题；
- 三项能力以自然换行文字呈现，不使用胶囊标签；
- 统一显示现有文案“成员信息待补充”，但每人不重复渲染小状态徽章；
- 不绘制占位头像框。

当真实资料到位时，只替换数据和可选图片，不改变整体署名结构。

### 7. 页尾

继续复用 `SiteFooter` 的原型边界说明。视觉上收束为黑底片尾字幕，明确 IoT、VOC、工单、配件、回访和 AI 服务尚未真实接入。

## 组件与数据边界

保持 `LandingContent` 为 Server Component 友好的页面组合根，并复用现有 `SiteHeader`、`SiteFooter`、`StatusTag` 和只读内容数据。

实现阶段应进行以下聚焦调整：

- 新建 `JourneyScene`：表达一个角色接力场景，不承载业务状态；
- 新建 `ServiceBlueprint`：表达五层路径、标注和闭环关系；
- 新建 `OutcomeStatement`：统一呈现三个方案目标；
- 将 `RoleCard` 和旧 `SignalFlow` 从首页组合中移除；如果没有其他调用方，则删除组件及其专用 CSS；
- 扩展 `Perspective` 数据，使每个视角包含场景对白或主动作；
- 继续使用现有 `ServiceLayer` 的输入、动作和输出，不复制第二份架构数据；
- CSS 只作用于 `.landing-shell`，不得改变现有工作台外观。

不增加客户端状态、滚动动画库、UI 框架、WebGL 或图片依赖。首版使用 CSS `position: sticky`、渐变、伪元素和媒体查询完成场景感；如果浏览器不支持 sticky，正常文档流仍可阅读。

## 动效

动效只围绕信号的“出现—传递—闭合”：

- 首屏温度波形轻微呼吸；
- 服务旅程中的线路在章节进入时呈现方向感；
- 五层蓝图使用一条缓慢移动的青绿扫描光；
- 文本以少量整组进入代替大量小元素依次弹出；
- 悬停不承担主要信息，不依赖鼠标才能读懂内容。

CSS 首版不监听精确滚动进度，因此不伪造复杂的同步时间线。所有动画遵循 `prefers-reduced-motion`；关闭动效后线路保持静态可见。

## 字号与密度约束

为避免回到“小框小字”模式，同时防止中文标题过度放大，建立以下硬约束：

- 桌面端主标题使用 `clamp(48px, 5vw, 72px)`，手机端最大不超过 `48px`；
- 章节标题使用 `clamp(34px, 4vw, 52px)`，不使用接近首屏标题的尺度；
- 核心角色价值文字使用 `clamp(22px, 2.4vw, 32px)`；
- 正文基准字号不低于 `16px`，行高不低于 `1.6`；
- 小于 `12px` 的文字只允许出现在页头辅助标记、技术刻度和页尾法律/原型说明；
- 主页最多保留两种胶囊/徽章用途：认证状态和方案边界；
- 不创建四列等宽功能卡、三列等宽团队卡或五列等宽架构卡；
- 圆角只用于交互按钮，主要叙事区块保持直角或无容器边界。

## 响应式与无障碍

- `JourneyScene` 的 sticky 双栏在 `900px` 以下回到自然单列；
- 任何装饰信号线、波形和温度刻度使用 `aria-hidden="true"`；
- 页面标题层级连续，角色场景使用语义章节和标题；
- CTA 与导航具备可见键盘焦点；
- 青绿不作为唯一状态编码，关键状态同时使用文字；
- 所有正文颜色满足 WCAG AA；
- 手机端不依赖视口高度锁定，避免地址栏变化导致内容被裁切；
- 关闭 CSS、动画或 sticky 后，内容顺序仍为首屏、四视角、五层、结果、团队、边界。

## 技术与产品边界

- 继续使用 Next.js App Router、React、TypeScript 和 CSS；
- 不新增 `/experience/*` 页面或死链；
- 不修改飞书 OAuth、Cookie、会话、认证路由和生产环境变量；
- 不接入真实 IoT、VOC、客服、工单、配件、回访或 AI 服务；
- 不把方案目标描述成已实现指标；
- 不修改 `/dashboard` 的现有视觉；
- 网页、仓库、URL 和字标继续使用 OneCare，正文可以出现海信；
- 本次仅重构主页叙事和视觉，不讨论或落地最终系统架构。

## 测试与验收

实现按 RED → GREEN → REFACTOR：

1. 先更新主页测试，断言新的连续旅程结构、四个场景、五层蓝图、结果段和团队署名；
2. 测试先因新结构不存在而失败；
3. 实现最小组件与样式后使测试通过；
4. 保持认证、工作台和运行时测试通过；
5. 运行 `npm test`、`npm run lint`、`npm run typecheck`、`npm run build`、`npm run test:runtime` 和 `git diff --check`。

人工验收需要确认：

- 首屏和各章节不再呈现为卡片墙；
- 四视角可以被理解为同一事件的连续接力；
- 五层架构是一张连续蓝图，并明确“学习 → 感知”的闭环；
- 关键正文在桌面和手机上都不依赖微型文字；
- 三位成员是署名式占位，不虚构资料；
- 页面没有 `/experience/*` 死链；
- `prefers-reduced-motion` 下内容完整；
- 现有飞书登录与 `/dashboard` 行为不变。
