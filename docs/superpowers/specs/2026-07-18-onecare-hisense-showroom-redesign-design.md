# OneCare 海信品牌展厅式首页视觉重构设计

## 状态与优先级

用户于 2026-07-18 否定当前“服务信号纪录片”首页的视觉结果，并要求重新建立一组不可违反的页面规则：

1. 所有按钮只能是圆形或药丸形；
2. 所有卡片必须使用圆角；
3. 页面主体背景为白色，最上方页头和最下方页尾为黑色；
4. 全站字体统一为 MiSans；
5. 顶部导航和四视角 Tab 的字号必须加大；
6. 可以使用海信美国官网的大幅背景图片；
7. 保留现有有效动效，但不再延续当前视觉构图。

本规格只定义首页视觉与交互重构，不进入最终系统架构讨论。它继承 `2026-07-17-onecare-homepage-design.md` 中的产品范围、认证边界、静态数据边界和 Preview 交付要求，但覆盖下列旧规则：

- 废止“主要叙事区块保持直角”的要求；
- 废止“首屏不使用真实设备图片或外部素材”的要求；
- 废止宋体标题、窄体英文标签和多字体混排；
- 废止主体章节交替使用整屏黑底或浅青底的要求；
- 废止四角色必须按四个超长滚动场景依次展示的要求；
- 废止小字号导航、微型技术标签和直角文字按钮。

如果旧规格与本规格冲突，以本规格为准。

## 设计研究依据

2026-07-18 对 [海信美国官网](https://www.hisense-usa.com/) 的桌面端、移动端、HTML 源码与浏览器计算样式进行了检查。只提取可复用的设计规律，不复制其 Wix 技术实现。

观察结果：

- 页头固定为约 `60px` 的纯黑横条，桌面端使用横向大写导航，移动端保留品牌、搜索和圆形菜单入口；
- 页面主体以白色为主，页尾是完整的大面积黑色信息区；
- 主色青绿的计算值为 `rgb(0, 164, 160)`，即 `#00A4A0`；
- 产品 CTA 使用 `border-radius: 50px` 的药丸形；大图 Hero 的描边 CTA 接近 `48px` 高；
- 资讯图片容器使用约 `20px` 圆角并裁切溢出；
- 主页大量使用横跨屏幕的大幅生活方式或产品图片；当前首屏响应式图片源尺寸达到 `2816 × 1048`；
- 中段常使用“大色块文案 + 大幅产品图”的二分构图，避免把所有内容缩进小卡片；
- 移动端继续让大图承担主要叙事，文本直接叠加在经过裁切的图片上，而不是退化成密集卡片列表。

海信官网当前标题使用其品牌字体，本项目不复刻该字体。用户已明确指定全站改为 MiSans，因此字体方案以 [MiSans 官方字体与许可](https://hyperos.mi.com/font/en/details/tc/) 为准。

## 设计方向

### 采用方案：海信品牌展厅 + OneCare 服务演示

首页应该像一个海信智能生活品牌展厅，而不是 AI SaaS 模板或数据控制台：

- 用黑色首尾建立清晰品牌框架；
- 用白色主体、宽阔留白和大幅真实场景图建立产品感；
- 用青绿药丸按钮和圆形图标按钮承载交互；
- 用圆角白色卡片承载需要被识别为独立对象的信息；
- 用四个大号 Tab 让评审主动切换用户、客服、工程师、后台视角；
- 用一张连续、圆角的系统总览解释“感知—诊断—编排—服务—学习”；
- 保留信号脉冲、分层进入和轻微图像运动，但动效必须服从大图和内容层级。

该方向不追求逐像素复刻海信官网，也不把 OneCare 伪装成零售商城。海信官网提供品牌语言，OneCare 的服务闭环案例提供信息结构。

## 不可违反的视觉规则

### 1. 按钮形状

页面中只允许两类按钮：

#### 药丸按钮

- 用于文字 CTA、导航状态、角色 Tab、登录、进入工作台和表单操作；
- `border-radius: 999px`；
- 桌面端高度 `48px`，紧凑导航按钮不得低于 `44px`；
- 水平内边距至少 `22px`；
- 主要按钮为青绿底黑字或黑底白字；次要按钮为透明底加 `1px` 描边；
- 不允许 `2px`、`4px`、`8px` 等轻微圆角的矩形按钮；
- 不允许单独使用带下划线的小字号文本充当主要 CTA。

#### 圆形按钮

- 只用于单图标操作，例如轮播前后、菜单、关闭、返回顶部和方向箭头；
- 宽高必须相等，`border-radius: 50%`；
- 标准尺寸 `48px`，移动端最低 `44px`；
- 图标必须居中并提供可访问名称；
- 不允许把两个以上文字塞进圆形按钮。

所有按钮必须具有 `hover`、`active`、`focus-visible` 和 `disabled` 状态。键盘焦点使用与背景清晰分离的双层描边，不只依赖颜色变化。

### 2. 卡片形状

所有语义上独立的卡片必须使用圆角和白色背景：

- 小卡片：`16px`；
- 标准内容卡：`20px`；
- 大型角色面板、系统面板：`28px`；
- Hero 内嵌浮层或超大媒体面板：最多 `32px`；
- 图片必须继承父卡片圆角并裁切溢出；
- 卡片背景统一为 `#FFFFFF`；
- 默认使用 `1px solid #E4E6E5` 分隔，不用厚重阴影；
- 浮起状态最多使用低透明度软阴影，禁止玻璃拟态和发光边框。

“卡片”是视觉上被边界包围、可独立识别的内容对象。全宽页头、全宽页尾、纯白章节背景、无容器的大图背景带不属于卡片，不强制加圆角。

### 3. 背景与分区

- `SiteHeader` 必须为 `#000000`；
- 首页主体画布必须为 `#FFFFFF`；
- `SiteFooter` 必须为 `#000000`；
- 主体章节不得再交替使用整屏黑底、深绿底或浅青底；
- 青绿只能用于按钮、活动状态、信号和少量关键强调；
- 浅灰只允许用于边框、分隔和轻量次级区域，不得把页面主体染成灰色；
- 大幅背景图可以覆盖白色画布，但必须被视为媒体章节，而不是新的主题背景色。

### 4. 字体与字阶

全站所有中文、英文、数字、按钮、导航、图表标注与页尾统一使用 MiSans：

```css
font-family: "MiSans", "PingFang SC", "Microsoft YaHei", sans-serif;
```

实施时优先使用官方 MiSans 简体中文可变字体或经许可的 WOFF2 子集，通过 `next/font/local` 或等价本地 `@font-face` 加载，并使用 `font-display: swap`。系统字体只作为加载失败回退。

禁止继续使用：

- `Songti SC`、`STSong` 或其他宋体；
- `Arial Narrow`、`DIN Condensed`；
- 为标签、数字或英文单独切换字体；
- 用全大写和极宽字距制造“技术感”。

固定字阶：

| 用途 | 桌面端 | 移动端 | 字重 |
| --- | --- | --- | --- |
| Hero 标题 | `clamp(52px, 5vw, 68px)` | `38–44px` | `600` |
| 章节标题 | `clamp(36px, 4vw, 48px)` | `30–36px` | `600` |
| 角色面板标题 | `32–40px` | `28–32px` | `600` |
| 四视角 Tab | `18–20px` | `17–18px` | `600` |
| 顶部锚点导航 | `16px` | `15–16px` | `600` |
| 正文导语 | `18–20px` | `17–18px` | `400` |
| 正文 | `16–18px` | `16px` | `400` |
| 辅助说明 | 不低于 `14px` | 不低于 `14px` | `400–500` |

Hero 标题不得超过两行，也不得回到占满整屏的超大中文标题。小于 `14px` 的正文、导航、Tab、卡片说明和按钮文字一律不允许。

### 5. 颜色令牌

```css
--onecare-black: #000000;
--onecare-white: #ffffff;
--onecare-teal: #00a4a0;
--onecare-teal-dark: #007d79;
--onecare-ink: #111312;
--onecare-muted: #5f6663;
--onecare-line: #e4e6e5;
--onecare-focus: #8fe8e3;
```

青绿来源于海信官网当前按钮的计算样式。禁止紫色渐变、彩虹渐变、霓虹发光和大面积浅青背景。图片自身可以包含更丰富的真实环境颜色。

## 页面结构

### 1. 黑色页头

继续复用 `SiteHeader`，但重做为海信官网式黑色品牌条：

- 高度 `64px`，滚动后保持顶部可见；
- 左侧为白色 OneCare 字标，不出现 Hisense；
- 中部显示“首页 / 四个视角 / 五层引擎 / 团队”锚点导航；
- 导航字号 `16px`、字重 `600`，不得使用微型英文标签；
- 右侧为药丸形“飞书登录”或“进入工作台”；
- 当前章节只通过青绿底部短线或文字颜色提示，不增加矩形标签；
- 移动端保留 OneCare、登录入口和圆形菜单按钮；菜单面板使用黑色背景，菜单项使用大字号，不允许横向挤压成小字。

### 2. 大图 Hero

首屏改为真正的大幅媒体场景：

- 黑色页头下方直接进入一张海信智能家庭或家电生活方式背景图；
- 桌面端媒体区域高度约 `min(72vh, 760px)`，移动端约 `68–76vh`；
- 图片使用 `object-fit: cover`，根据桌面和移动端分别定义焦点位置；
- 通过从黑色半透明到透明的局部渐变保证文字可读，不使用整图灰化；
- 文案保留“让每一次服务，都比问题更早一步”，使用 MiSans 中等字重；
- 主 CTA“查看四个视角”为青绿药丸按钮；次 CTA 为白色描边药丸按钮；
- 可以保留温度异常脉冲作为叠加层，但只占据局部，不遮挡主体图像；
- 不在首屏堆叠状态徽章、小卡片、技术参数框或多段免责声明。

图片中的原有海信品牌或产品可以保留，但不得让 OneCare 页面名称、仓库名称或 URL 改成 Hisense。避免选择已经内嵌大量英文广告文案的图片作为文字叠加底图。

### 3. 四视角 Tab 演示

四个视角恢复为页面最重要的可交互展示，而不是四个连续超长章节。

Tab 顺序：

1. 用户；
2. 客服；
3. 工程师；
4. 后台。

交互规则：

- Tab 使用药丸按钮组成单行切换组；
- 桌面端字号 `18–20px`，高度 `52px`；移动端字号 `17–18px`，高度 `48px`；
- 活动 Tab 为青绿底黑字，非活动 Tab 为白底黑字加灰色描边；
- Tab 区在窄屏允许横向滚动，但每项不得缩小字体；
- 使用 `role="tablist"`、`role="tab"`、`role="tabpanel"`；
- 支持左右方向键、`Home`、`End` 和可见焦点；
- 默认选中“用户”，切换后不改变 URL、不请求后端、不伪造真实服务数据。

每个 Tab 对应一个大型圆角角色面板：

- 圆角 `28px`，白色背景；
- 桌面端使用“场景图 / 产品界面演示”与“角色价值 / 关键动作”的宽幅二分构图；
- 移动端先图后文；
- 每个面板只保留一个角色标题、一句价值主张、三项关键动作和一条服务交接结果；
- 关键动作使用直接文本或带图标的短行，不再使用大量微型胶囊标签；
- 用户面板可以预告后续 AI 聊天智能体，但本阶段不实现真实聊天；
- 角色面板之间复用同一个组件和数据结构，只替换内容、图片和强调状态。

### 4. 五层引擎

“感知—诊断—编排—服务—学习”使用一张大型圆角白色系统面板，不拆成五张等权小卡：

- 外层圆角 `28px`、白底、浅灰边框；
- 五层在桌面端用一条横向青绿路径连接，在移动端改为纵向；
- 每层名称使用至少 `22px`，输入、动作、输出正文至少 `16px`；
- 当前冰箱温控异常案例通过五个圆形节点沿路径推进；
- “学习 → 感知”用一条明确回流线或回流说明闭合；
- 辅助信息直接排在路径附近，不再嵌套多个小框；
- 不使用深色整屏架构背景，不使用发光网格或粒子背景。

### 5. 结果与价值

“更短服务周期 / 更低重复上门 / 更高用户满意”继续明确标注为方案目标：

- 使用一个白色章节和三段大号文字；
- 可以用三个圆形青绿序号或图标建立节奏；
- 不使用伪造数字、百分比或生产指标；
- 不把三项目标重新包装成三张小数据卡。

### 6. 团队

团队区域使用三张标准圆角白卡：

- 卡片圆角 `20px`，浅灰描边；
- 真实信息未提供前继续显示“成员信息待补充”，不虚构姓名和履历；
- 每张卡只包含成员序号、角色方向、能力说明和可选照片；
- 能力以自然文本或三行列表展示，不使用密集胶囊标签；
- 桌面端三列，平板两列，手机单列；
- 未来补充照片时使用圆形头像或圆角图片，不能使用直角照片框。

### 7. 黑色页尾

页尾参考海信官网的大面积黑色信息区：

- 背景 `#000000`，文字为白色和中性灰；
- 明确 OneCare 原型边界；
- 提供四视角、五层引擎、团队和返回顶部入口；
- 返回顶部使用青绿色圆形按钮；
- 页尾链接字号不低于 `15px`；
- 不再使用细小的片尾字幕式排版。

## 海信官网图片使用规范

用户已确认海信美国官网的大背景图可以用于本原型。实施阶段遵守以下规则：

1. 从官网当前页面选择 `2–4` 张与智能家庭、冰箱、服务或家庭生活相关的大图；
2. 优先选择无内嵌广告文字、留有安全文字区、能在移动端合理裁切的图片；
3. 图片下载到 `public/images/hisense/`，不直接热链 Wix CDN；
4. 新增 `public/images/hisense/SOURCES.md`，记录原页面、原始素材 URL、获取日期、用途和裁切说明；
5. 保留原图比例，同时生成或使用 AVIF/WebP 优化版本；
6. Hero 桌面资源目标不超过 `700KB`，章节图片目标不超过 `350KB`；
7. 使用 Next.js `Image`、正确的 `sizes` 和明确尺寸，Hero 作为 LCP 图片优先加载，其余图片延迟加载；
8. 不对品牌或产品做误导性合成，不把图片解释成已经接入 OneCare 的真实业务案例；
9. 图片仅用于本次 OneCare 比赛原型与其 Preview/演示站，不作为独立素材包分发。

当前官网大图可以作为候选素材池，但实施前必须在桌面和移动裁切预览中确认文字与主体不冲突。

## 组件与复用设计

保持技术栈和脚手架不变，建立以下共享边界：

- `PublicPageShell`：统一黑色页头、白色主体和黑色页尾；
- `PillButton`：统一文字按钮、登录入口和 Tab 的形状及状态；
- `CircleButton`：统一图标操作；
- `SurfaceCard`：统一白色背景、圆角、边框和可选媒体裁切；
- `HeroMedia`：统一响应式大图、渐变、文字安全区和 CTA；
- `PerspectiveTabs`：唯一需要客户端状态的四视角 Tab；
- `PerspectivePanel`：复用四个角色面板结构；
- `ServiceEngine`：复用五层架构数据并渲染一张连续系统面板；
- `SiteHeader`、`SiteFooter`：继续作为所有公开页面的公共组件。

共享组件只抽取稳定规则，不创建高度参数化的万能组件。首页静态内容继续保存在只读 TypeScript 数据中；认证 URL 和会话状态继续由现有服务端边界提供。

## 动效

保留用户认可的动效质量，但改变其服务对象：

- Hero 首次进入：图片轻微缩放回落，标题和 CTA 分两组进入；
- 温度信号：低频脉冲，不持续闪烁；
- Tab 切换：面板使用 `180–240ms` 的淡入与小幅位移，图片和文字同步；
- 圆角卡片进入：整张卡片出现，不让每一行文字分别弹跳；
- 五层引擎：青绿信号沿单一路径缓慢推进；
- 按钮悬停：背景、描边和箭头位移，禁止夸张缩放；
- 大图可使用极轻微视差，但移动端关闭。

所有动效遵循 `prefers-reduced-motion`。关闭动效后不得隐藏内容、改变 Tab 可用性或破坏阅读顺序。

## 响应式规则

### 桌面端：`≥ 1200px`

- 页头完整显示主导航；
- Hero 使用宽幅大图；
- 四个 Tab 单行居中或左对齐；
- 角色面板和品牌场景使用二分构图；
- 五层引擎横向展示；
- 团队三列。

### 平板端：`768–1199px`

- 页头允许缩短导航间距，但不缩小到 `16px` 以下；
- 角色面板保持二分或根据空间切换为上下结构；
- 五层引擎可改为两段折线路径；
- 团队两列。

### 移动端：`< 768px`

- 黑色页头保留 `60px` 左右高度；
- Hero 使用独立移动裁切焦点，标题不超过 `44px`；
- 四视角 Tab 横向滚动，字号不低于 `17px`；
- 角色面板、系统面板和团队卡单列；
